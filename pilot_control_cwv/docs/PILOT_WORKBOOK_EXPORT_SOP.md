# Pilot Workbook Export SOP

## Purpose

Standardize how the daily pilot KPI workbook is exported and handed off to the
shared `Guest_Card_Reports` directory after a successful report run.

This SOP applies to the companion workbook:

- `Pilot_KPI_Summary_Details_Full_YYYY-MM-DD.xlsx`

## Source and Destination

Source workbook generated by the reporting pipeline:

- `/Users/mark/Property_Analytics/pilot_control_cwv/reports/Pilot_KPI_Summary_Details_Full_YYYY-MM-DD.xlsx`

Shared delivery destination:

- `/Users/mark/Library/CloudStorage/OneDrive-VenterraRealty(Canada)Inc/Guest_Card_Reports/`

## Trigger

Run this SOP after:

1. the latest BI workbook has been ingested
2. the latest Measurement workbook has been ingested
3. dashboard snapshots have been regenerated
4. the companion workbook has been generated successfully

## Required Output

At the end of the run, the same-day workbook must exist in both locations:

1. `pilot_control_cwv/reports/`
2. `Guest_Card_Reports/`

Example:

- local build artifact:
  - `/Users/mark/Property_Analytics/pilot_control_cwv/reports/Pilot_KPI_Summary_Details_Full_2026-04-09.xlsx`
- shared delivery copy:
  - `/Users/mark/Library/CloudStorage/OneDrive-VenterraRealty(Canada)Inc/Guest_Card_Reports/Pilot_KPI_Summary_Details_Full_2026-04-09.xlsx`

## Manual Command

After the workbook is generated, copy it into the shared directory:

```bash
cp /Users/mark/Property_Analytics/pilot_control_cwv/reports/Pilot_KPI_Summary_Details_Full_YYYY-MM-DD.xlsx \
  "/Users/mark/Library/CloudStorage/OneDrive-VenterraRealty(Canada)Inc/Guest_Card_Reports/Pilot_KPI_Summary_Details_Full_YYYY-MM-DD.xlsx"
```

## Verification

Confirm all of the following:

1. The workbook exists in `pilot_control_cwv/reports/`
2. The workbook exists in `Guest_Card_Reports/`
3. The copied filename matches the run date exactly
4. The workbook opens successfully from the shared directory
5. The tracker/dashboard refresh and workbook run completed without source-integrity fallbacks

## Notes

- The workbook file date reflects the run/package date.
- Source data coverage may lag by one day because of collection timing.
- This copy step is a delivery/export step only. It does not change source data.
- Missing values must remain explicit; this SOP does not permit any data filling or workbook editing during export.

## Relation to Depository Workflow

This SOP is separate from the internal pilot report depository sync:

- internal depository sync organizes artifacts under:
  - `pilot_control_cwv/reports/depository/`
- this SOP places the delivery workbook in the shared operational directory used by stakeholders:
  - `Guest_Card_Reports/`

Both should happen on a normal daily run.

## Directory Housekeeping

After the workbook has been copied into `Guest_Card_Reports`, archive all
consumed source drops except:

- `Measurement_Dashboard_1.1.xlsx`
- the current same-day companion workbook

Housekeeping command:

```bash
python3 /Users/mark/Property_Analytics/pilot_control_cwv/scripts/housekeep_guest_card_reports.py \
  --run-date YYYY-MM-DD
```

This moves files such as BI drops and website CSV exports into:

- `/Users/mark/Library/CloudStorage/OneDrive-VenterraRealty(Canada)Inc/Guest_Card_Reports/Archive/`
