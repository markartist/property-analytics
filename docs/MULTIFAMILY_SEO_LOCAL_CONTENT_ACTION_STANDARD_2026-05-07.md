## Purpose

This standard turns the VP multifamily SEO/GEO/AEO/AIO instruction document into a governed Data Pond and Captain reporting lane. It is an additive content-action layer, not a replacement for PIB, Watchlist Decision Output, Captain Brief, Site Content Creator, or the VP retrieval JSON.

The core rule is simple: do not produce generic SEO advice. Every copy, GBP, social, FAQ, metadata, or shadow-page recommendation must tie to the property's actual leasing condition and the current website's real content gaps.

## Canonical Ownership

- Data source owner: Data Pond / Data Collection
- Content diagnosis owner: Site Content Creator + Specs Memory
- Operating report owner: Watchlist / Captain report family
- Execution artifact owner: Content Operations / Site Content Creator

Do not create a separate SEO report renderer or one-off email path when the recommendation is being used inside a Watchlist, Captain, PIB, or Site Content Creator workflow.

## Required Inputs

Use both input groups whenever available:

- Property operating/performance evidence:
  - exposure and available units
  - highest-pressure floorplans or unit types
  - T30/T90 guest cards, visits, applications, PQ, leases, move-ins
  - pricing/value posture, specials, concessions, and competitor market pressure
  - reputation and review friction
  - GA4, GBP, PSI/CWV, GSC, and DataForSEO/on-page snapshots
- Website/page evidence:
  - property URL
  - title tag, meta description, H1/H2 structure
  - homepage word count and content density
  - page hierarchy and internal links
  - current hero/value/special/location/FAQ copy
  - crawlable child-page availability

If one input group is absent, proceed only when useful, and label the limitation in the source/evidence lane instead of inventing facts.

## Decision Logic

Prioritize content work in this order:

1. Floorplans or unit types with the highest exposure.
2. Units or products with the longest market friction where current evidence supports it.
3. Messaging gaps that weaken conversion.
4. Weak local/entity relevance on the website or GBP.
5. Renter questions not clearly answered.
6. GBP/local content opportunities that can drive near-term qualified discovery.

The recommended angle must come from the strongest supportable evidence:

- value
- location convenience
- floorplan availability
- service/reputation strength
- amenities or differentiators
- current specials or offers
- practical renter utility

Do not force a luxury, lifestyle, employer, commute, or neighborhood claim unless the source evidence supports it.

Preferred action areas:

For execution artifacts, the same lane can expand into:

- shadow-page copy

- website + GBP FAQs

- exact social copy

## Guardrails

- Do not invent facts, distances, employers, landmarks, specials, unit availability, competitor offers, or rankings.
- Use approximate language only where the source supports a reasonable approximation.
- Use Fair Housing-conscious language.
- Avoid exclusionary, coded, demographic-preference, family-status-coded, or steering language.
- Avoid generic apartment filler such as "luxury living at its finest," "modern living redefined," and "where comfort meets convenience."
- Prefer specific, useful renter-facing language.
- Do not keyword stuff.
- Do not create thin shadow pages.
- Do not add more homepage copy when the real issue is topic dilution or weak page hierarchy.
- Audit first, synthesize second, rewrite third.
