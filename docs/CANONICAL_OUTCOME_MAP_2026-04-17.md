# Canonical Outcome Map

Status: Draft v1
Date: 2026-04-17
Owner: MarketingOps / Property Analytics
Scope: Outcome-based canonical ownership map for consolidating the full web platform into one governed operating system

## 1. Why This Exists

The platform no longer has a capability shortage.

The real remaining risk is duplicate ownership for the same outcome.

This map answers:

- what major outcomes the platform exists to produce
- who canonically owns each outcome
- which specialized systems are acceptable
- which systems should be consolidated now

This is the enterprise-grade layer between:

- capability inventory
- control-plane visibility
- repo cleanup
- product and security architecture

## 2. Governing Rule

One canonical owner per outcome.

Multiple implementations are only acceptable when they serve:

- a temporary pilot purpose
- an imported/specialized adjacent purpose
- a clearly different audience or time horizon

## 3. Canonical Outcomes

### 3.1 Operational Health

Canonical owner:

- Watchtower + Data Collection

Mission:

- health
- freshness
- closure state
- retry posture
- trust pressure
- operational visibility

Consolidate now:

- Portfolio Monitoring overlap
- legacy health viewpoints duplicating Watchtower outcomes

Accepted specialization:

- pilot monitoring programs may stay outside while consuming canonical health truth

### 3.2 Portfolio Briefing

Canonical owner:

- PIB / POP Brief family through The Pond

Mission:

- portfolio and property briefing
- executive interpretation
- stable report-family architecture

Consolidate now:

- loose briefing/report-family sprawl across PIB, POP Brief, Spotlight, and imported report structures

Accepted specialization:

- Spotlight / imported POP-related reporting may remain specialized while the family is organized

### 3.3 Portfolio Insight and Navigation

Canonical owner:

- Dock + Pond product surfaces

Mission:

- portfolio movement
- report entry
- operator navigation
- modern insight presentation

Consolidate now:

- Portfolio Dashboard overlap with Dock and app-native analysis surfaces

### 3.4 Content Operations

Canonical owner:

- Intelligence Office + Site Content Creator + VACS

Mission:

- interpretation
- directives
- governed rewrite execution
- channel-aware content generation

Consolidate now:

- content efforts that bypass the governed spine

Accepted specialization:

- Specs remains an external governed sibling

### 3.5 Validation and Experience

Canonical owner:

- EVS

Mission:

- staging-first validation
- experiential evidence
- mixed human-and-machine validation lifecycle

Consolidate now:

- ad hoc screenshot/manual validation flows that should route through EVS

### 3.6 Data Truth and Collection

Canonical owner:

- Data Pond + Data Collection

Mission:

- normalized truth
- lineage
- freshness
- shared APIs
- run state

Consolidate now:

- Portfolio Monitoring retaining canonical collection ownership
- script-only truth assumptions outside canonical collection paths

## 4. Accepted Specializations

These are acceptable to remain outside the main Pond as long as they stay known and do not silently become canonical:

- `pilot_control_cwv`
- `pilot_roundup`
- `Spotlight_Properties_Report`

## 5. Consolidate-Now Systems

### Portfolio_Monitoring

Target owner:

- Data Collection + Watchtower

Reason:

- still overlaps operational visibility and collection ownership

### Portfolio_Dashboard

Target owner:

- Dock + Pond product surfaces

Reason:

- still overlaps portfolio navigation and insight outcomes

### Brief-family sprawl

Target owner:

- PIB / POP Brief family through The Pond

Reason:

- too many loosely related briefing/report paths target the same stakeholder understanding outcome

## 6. Enterprise Rules

- no new parallel dashboard for an existing outcome
- no new script-only canonical system when a Pond or API contract exists
- no private canonical truth outside the Data Pond
- Keeper + Cloudflare Zero Trust + app roles is the default security posture
- nested repos are explicit boundary objects, not silent homes for net-new canonical ownership
