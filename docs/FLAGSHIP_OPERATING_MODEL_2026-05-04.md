# The Flagship Operating Model

Status: Draft v1
Date: 05/04/2026
Owner: MarketingOps / Property Analytics
Scope: Command structure, operating cadence, and method for running Marketing Operations as The Flagship

## Definition

The Flagship is the operating model for Marketing Operations.

It is the command system that connects:

- governed source evidence
- property identity
- role ownership
- memory
- recurring reads
- action accountability
- executive escalation

Marketing Operations is the department. The Flagship is how the department runs.

## What The Flagship Must Provide

The Flagship should provide:

- one governed property identity system
- one property command structure
- one memory model
- one method for moving from facts to directives
- one standard for recurring reads and escalations
- one action-accountability model
- one doctrine path for promoting lessons into reusable operating guidance

## Operating Layers

| Layer | Job |
| --- | --- |
| Data Pond | governed internal fact base and source-of-record landing zone |
| Source Lanes | collection, mirroring, quality checks, and external evidence capture |
| Captain Runtime | property-scoped interpretation, watch generation, action generation, memory maintenance |
| Command Reads | Captain, Commodore, and Admiral outputs for operating decisions |
| Doctrine And Memory | promoted lessons, standards, and historical learning |

## Command Hierarchy

The Flagship uses the established command language already defined in the Captain hierarchy standard.

| Role | Job In The Flagship |
| --- | --- |
| Fleet Commander | sets department doctrine, operating priorities, and portfolio posture |
| Chief of Staff | coordinates system design, standards, workflows, and cross-capability execution |
| Admiral | receives executive reads and resolves high-level property or portfolio decisions |
| Commodore | manages a cohort, region, or portfolio slice; promotes patterns and escalations |
| Captain | owns one property's intelligence, memory, support lanes, and directive quality |
| First Officer | validates field reality and executes local follow-through with the Captain |
| Quartermaster | owns source integrity, arrival, freshness, and evidence confidence |
| Navigator | owns search, content, SEO, entity, and demand-path intelligence |
| Signals Officer | owns channel, media, attribution, and source-performance intelligence |
| Engineer | owns runtime, automation, site-validation, and system reliability posture |
| Boatswain | owns action tracking, follow-up, and closure verification |
| Logkeeper | owns memory quality, lineage, and doctrine-candidate preservation |

## Property Designations

The Flagship uses property designations as command posture inputs.

| Designation | Command Meaning | Expected Effect |
| --- | --- | --- |
| Critical | acute risk or urgent executive attention | tighter cadence, faster escalation, stronger action discipline |
| Spotlight | active strategic watch property | regular briefing, current read quality, standard command intensity |
| Sale | leasing or revenue urgency posture | stronger emphasis on exposure, pricing, concessions, funnel pressure, and pace |

Designation is not export decoration. It changes how the system allocates attention.

## Standard Method

Every Captain cycle in The Flagship follows six steps.

### 1. Collect

- gather current evidence from governed internal and external sources
- validate arrival, freshness, identity resolution, and lane coverage
- mark missing or stale lanes explicitly

### 2. Reconcile

- compare source outputs
- resolve conflicts using source authority rules
- preserve unresolved disagreements as visible risk rather than smoothing them away

### 3. Diagnose

- identify what changed
- distinguish symptom from cause
- determine the primary constraint, such as traffic, conversion, pricing, inventory, operations, reputation, or source quality

### 4. Direct

- define the recommended action set
- assign owners, due dates, and expected effect
- define the measurement source that will prove whether the action worked

### 5. Track

- review open actions, blocked actions, and stale actions
- escalate slippage or ownership gaps
- verify closure against the expected proof source

### 6. Learn

- record what happened, what was expected, and what was learned
- preserve property-local lessons and promote cross-property lessons when justified
- update memory so future reads begin from reality instead of rediscovery

## Operating Cadence

### Daily

- source freshness and runtime health review
- Critical-property lane review
- overnight failures and mirror exceptions
- blocked-action scan
- command summary of top risks

### Weekly

- Captain briefs for active designated properties
- Commodore pattern scan across active roster
- source-quality review for degraded or stale lanes
- action closure review
- watchlist promotion and escalation decisions

### Monthly

- property roster refresh and designation update
- Captain activation and retirement review
- doctrine tuning and threshold review
- memory promotion review
- operating model audit of coverage, freshness, and follow-through

### Ad Hoc

- emergency scans
- post-launch or post-change validation
- executive decision requests
- issue-specific recovery directives

## Standard Command Questions

The Flagship should make these questions answerable for any active property.

- What changed?
- Why did it change?
- What is the governing evidence?
- What is the primary constraint right now?
- What action should happen next?
- Who owns that action?
- How will we know whether it worked?
- What should be remembered next cycle?

## Output Discipline

Every governed Flagship output should preserve:

- a named audience
- a defined owner
- evidence lineage
- source-confidence posture
- action ownership
- memory carry-forward

No output should hide stale lanes, missing sources, or unresolved conflicts.

## Promotion Path

The Flagship promotes learning through a governed ladder.

| From | To | Trigger |
| --- | --- | --- |
| Captain memory | Commodore memory | lesson matters across multiple properties or a regional pattern |
| Commodore memory | Fleet guidance | repeated lesson merits portfolio operating attention |
| Fleet guidance | doctrine artifact | lesson becomes durable reusable standard |

## Efficiency Rules

The Flagship should operate with the following rules.

- no duplicate truths
- no local one-off property mappings where the identity matrix can govern
- no action without an owner, date, and proof path
- no executive read without evidence lineage
- no active property without a Captain or known support-lane posture
- no memory promoted upward without source lineage
- no polished artifact that conceals source weakness

## Outcome Standard

A mature Flagship gives leadership fewer dashboards to interpret and more confidence in what to do next.
