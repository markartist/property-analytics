# Flagship Command Templates

Status: Draft v1
Date: 05/04/2026
Owner: MarketingOps / Property Analytics
Scope: Standard command-read structures for Captain, Commodore, and Admiral outputs in The Flagship

## Purpose

The Flagship needs repeatable read structures so every level of command sees the same operating truth at the right altitude.

These templates standardize what each command layer should answer, how much detail it should carry, and what decisions it should drive.

## Reading Ladder

| Layer | Audience | Primary Job |
| --- | --- | --- |
| Captain Read | property-scoped operators and support lanes | explain what is happening at one property and what must happen next |
| Commodore Read | regional, cohort, or portfolio operating leadership | identify patterns, repeated blockers, and resource or doctrine escalations |
| Admiral Read | executive leadership | surface the highest-signal decision request with consequence and urgency |

## Captain's Brief Template

The Captain's Brief is the full property command artifact.

### Required Sections

1. Property Header
- property name
- property code
- designation
- current cadence window
- source confidence posture

2. Admiral Read
- one short executive summary paragraph
- what changed
- why it matters now
- what decision or action matters most

3. Captain Read
- current operating condition
- primary constraint
- what the Captain believes is driving the condition
- what should happen next

4. Evidence Snapshot
- demand
- funnel
- inventory/exposure
- pricing or concession posture when available
- reputation/trust
- website/search/entity condition
- source-readiness caveats

5. Risk Watchlist
- risk
- why it made the list
- owner
- next move
- proof source

6. Action Register
- action
- owner
- due date
- expected effect
- proof source
- status

7. Memory Carry-Forward
- what should be remembered next cycle
- what failed, worked, or remains unresolved

### Captain Questions

Every Captain's Brief should answer:

- What changed in the last 7 and 30 days?
- What is the primary constraint?
- Which sources are trustworthy, weak, or stale?
- What action should happen next?
- Who owns it and how will we measure success?

## Commodore Read Template

The Commodore Read is a portfolio or cohort synthesis, not a stack of property summaries.

### Required Sections

1. Command Summary
- top risks across the cohort
- top opportunities across the cohort
- command posture by designation mix

2. Pattern Table
- pattern
- properties affected
- governing evidence
- whether the issue is source, market, funnel, inventory, reputation, or execution related

3. Escalation Register
- property
- issue
- why normal Captain handling is not enough
- required support or decision
- escalation owner

4. Doctrine Candidates
- repeated lesson
- where it showed up
- why it may deserve promotion to Fleet guidance

5. Resource Pressure
- lanes or source systems under strain
- missing coverage or blocked execution paths
- where leadership intervention would remove repeated friction

### Commodore Questions

Every Commodore Read should answer:

- Which property problems are actually the same problem repeating?
- Which Captains need help, decision support, or a source fix?
- What should become portfolio guidance rather than a local workaround?

## Admiral Read Template

The Admiral Read is short, severe, and decision-oriented.

### Required Structure

1. Situation
- what changed
- where it matters most
- why leadership should care now

2. Decision Need
- what decision is needed
- by whom
- by when

3. Evidence Basis
- the 2 to 5 facts that justify the request
- include any source-confidence caveat that changes the recommendation

4. Consequence
- what happens if we act
- what happens if we do not act

### Admiral Questions

Every Admiral Read should answer:

- What is the issue?
- Why now?
- What do you want me to decide or approve?
- What is the expected effect?

## Action Register Standard

All command layers should use the same action grammar.

| Field | Requirement |
| --- | --- |
| Action | specific, observable next move |
| Owner | named human or named lane |
| Due date | explicit date |
| Expected effect | concrete operating outcome |
| Proof source | governed source that will confirm progress |
| Status | open, blocked, overdue, closed, or needs decision |

## Confidence Standard

Every read should explicitly state confidence posture when it matters.

Use these plain terms:

- High confidence
- Working confidence
- Limited confidence
- Blocked confidence

If confidence is reduced by source gaps, stale lanes, or unresolved conflicts, say so plainly.

## Output Rule

These templates should reduce ambiguity, not add ceremony.

If a section is empty because the source chain is weak, the artifact should say that rather than filling the space with generic language.
