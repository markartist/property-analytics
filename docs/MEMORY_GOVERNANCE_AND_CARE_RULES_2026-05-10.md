# Memory Governance And Care Rules

Date: 05/10/2026

## Governance Checks

Before memory can be used, shown, summarized, or routed, the system checks:

- actor authorization through PropertyAccessControl
- visibility scope
- memory class
- lifecycle state
- freshness
- sensitivity
- allowed uses
- blocked uses
- steward rules
- care metadata
- correction path
- expiration
- source authority

## Blocking Rules

- Agent self notes cannot be used as public copy, report publication evidence, or Scribe input.
- Unverified human-submitted memory cannot be public copy.
- Relationship context cannot be used for performance scoring.
- Expired or archived memory cannot drive active recommendations unless explicitly surfaced as historical.
- Restricted memory cannot be shared upward except through allowed historical/self-reminder contexts.
- Quartermaster can block publishability-related memory use.
- Fleet Scribe remains publication authority.

## Correction And Archive

Every memory item requires a correction path. Memory can expire, archive, or be superseded. Archive language must be respectful and nonpunitive.
